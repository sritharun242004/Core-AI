<Hook>How do we change a pretrained policy's behavior without confusing a lower toy loss for alignment?</Hook>

<Intuition>
A pretrained causal LM has learned to continue text. Post-training changes the distribution of continuations: supervised examples teach a response format, preference data says which of two responses is better, and a policy update tries to increase the probability of the preferred behavior without destroying useful language ability. These are distinct contracts, not interchangeable labels.

This week follows one response through its anatomy: tokenize a prompt and completion, run a causal transformer, mask the supervised loss, freeze a reference policy, compare sequence log-probabilities, and update a small adapter. The project uses categorical ids held in memory, not a downloaded model or corpus. That makes the mechanics falsifiable while making the quality boundary unusually clear.

<IntuitionCallout>The offline result can establish tensor shapes, finite gradients, identity-preserving adapters, a decreasing fixture loss, and exact checkpoint restoration. It cannot establish instruction following, harmlessness, factuality, preference quality, or a company's private post-training recipe.</IntuitionCallout>

## 1. The post-training map

A useful system diagram separates data, policy, evaluator, and update:

```text
pretraining corpus -> causal LM weights θ0
                              │
       demonstrations ────────┼──> SFT policy πSFT
                              │
       chosen/rejected pairs ┼──> preference objective -> policy π
                              │             ▲
       human / AI / rule feedback ──────────┘
                              │
       held-out prompts + safety/evals -> evidence about behavior
```

**Pretraining** learns broad next-token statistics from a corpus. **Post-training** selects a narrower behavior distribution under a prompt format and an evaluation protocol. SFT, reward-model training, RL, and direct preference objectives may all appear in a program, but a model card or paper must identify which stage produced which result.

A lower training loss is not a universal quality measure. It may show that labels are reachable, while hiding memorization, prompt leakage, length bias, refusal regressions, or a mismatch between the objective and the user-facing task. A post-training report should include a base checkpoint, data provenance and license, tokenizer/template, held-out prompts, safety slices, preference agreement, KL or drift measures, seed, and compute.

<Gotcha>“Aligned” is not a loss value. Alignment is a claim about behavior under stated values, evaluators, distributions, and failure tests. A finite preference loss is one plumbing signal inside that much larger claim.</Gotcha>

## 2. Full anatomy of a tiny causal policy

### Tokens, positions, and the causal direction

Week 14's byte-pair encoding (BPE) produces token ids. A prompt and completion become one sequence:

```text
<BOS> user:  Explain LoRA.  assistant:  LoRA adds a low-rank update. <EOS>
  x0       x1 ... xT-1
```

A decoder-only model uses a triangular attention mask so position `t` cannot read tokens after `t`. The representation starts with a token embedding and a position embedding:

<MathBlock latex="h_t^{(0)}=E[x_t]+P[t]" />

For hidden states `H`, each block forms queries, keys, and values:

<MathBlock latex="Q=HW_Q,\qquad K=HW_K,\qquad V=HW_V" />

and applies causal self-attention:

<MathBlock latex="\operatorname{Attn}(H)=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}+M_{causal}\right)V" />

The feed-forward sublayer then applies a position-wise nonlinear map, with residual paths and normalization around the attention and MLP. A final linear head maps each hidden state to a vocabulary logit:

<MathBlock latex="z_t=W_{out}\operatorname{Norm}(h_t),\qquad p(x_{t+1}\mid x_{\le t})=\operatorname{softmax}(z_t)" />

The tiny project keeps one transformer block readable. It ties the output matrix to the token embedding, but this is a parameter-saving teaching choice, not a claim about all decoder LMs.

### SFT loss and masking

For a target token sequence `y`, next-token cross-entropy is:

<MathBlock latex="\mathcal{L}_{SFT}=-\sum_t m_t\log\pi_\theta(y_t\mid x_{<t})\big/\sum_t m_t" />

`m_t` can be one for completion tokens and zero for prompt tokens. Some implementations shift input and labels in the model; others prepare shifted labels in a collator. Either is correct when the alignment is tested. The reference project uses already aligned SFT labels and `-100` as the ignored target sentinel. Its generic `sequence_logprob` helper does not shift; its DPO batch helper explicitly shifts full causal ids and masks before scoring, and can sum or token-normalize selected targets.

Prompt masking prevents the model from being rewarded for reproducing the user instruction, but it does not make the completion truthful or safe. Packing examples changes boundaries and requires attention/label masks. Padding requires a pad policy. Truncation can delete the instruction or the answer. These are data-contract decisions, not incidental details.

### Checkpoint and evaluation contracts

A training step is only reproducible if it names model revision, tokenizer, template, sequence length, batch and gradient accumulation, precision, optimizer, learning rate, seed, data order, checkpoint interval, and evaluation prompts. Checkpoints should store model state, optimizer state when resuming, scheduler/scaler state when applicable, step, and configuration. Load only trusted checkpoint files.

The toy's decreasing loss and exact CPU state restoration are deliberately modest. They test that a policy can be trained and resumed; they do not test that it learned the intended instruction semantics.

## 3. SFT is behavior cloning, not preference understanding

SFT copies demonstrations. If an expert response is `y*`, maximizing its token likelihood increases:

<MathBlock latex="\log\pi_\theta(y^*\mid x)=\sum_t\log\pi_\theta(y_t^*\mid x,y_{<t}^*)" />

Teacher forcing supplies the reference prefix even when the model would have made an earlier mistake. At inference, errors feed back into later positions. This exposure-bias gap is one reason a low teacher-forced loss does not guarantee robust generation.

A practical SFT dataset has at least these fields:

| field | question to answer |
| --- | --- |
| prompt and context | what is the user asking, and what information is authorized? |
| completion | which exact tokens are supervised? |
| provenance | who wrote or generated it, under which license? |
| template/version | how are roles, tools, EOS, and refusal markers encoded? |
| quality/safety label | what was filtered, and what was intentionally retained? |
| split | can a near-duplicate leak from train into evaluation? |

Synthetic demonstrations can increase coverage and make formatting consistent. They can also amplify teacher errors, stylistic artifacts, hidden assumptions, and evaluator shortcuts. Keep the generator and filtering policy versioned, and evaluate synthetic-only, human-only, and mixed slices when the claim matters.

## 4. Preference learning: RLHF, DPO, and the neighboring family

### Reward modeling and RLHF

Classical RLHF commonly has three stages:

1. SFT initializes a helpful policy.
2. A reward model `r_\phi(x,y)` learns from preference pairs `(y^+,y^-)`.
3. An RL optimizer updates the policy while regularizing it toward a reference policy.

A schematic KL-regularized objective is:

<MathBlock latex="\max_\pi\;\mathbb{E}_{x,y\sim\pi}[r_\phi(x,y)]-\beta\,D_{KL}(\pi(\cdot\mid x)\parallel\pi_{ref}(\cdot\mid x))" />

The reward model is an evaluator, not ground truth. It can be miscalibrated, overfit to annotator style, blind to subtle harms, or gamed by verbosity. PPO-style RL adds rollout, value estimation, clipping, and operational complexity. The distinction between reward-model score, human preference, and user outcome should remain explicit.

### DPO — a direct preference objective

This lesson attributes **Direct Preference Optimization to Stanford's Rafailov et al. (2023)**. Their key move is to solve the KL-regularized preference problem in terms of a policy/reference log-ratio, eliminating a separately sampled reward-model/RL loop for the direct objective.

For chosen response `y^+`, rejected response `y^-`, policy `\pi_\theta`, and frozen reference `\pi_ref`, define:

<MathBlock latex="m=\left[\log\pi_\theta(y^+|x)-\log\pi_\theta(y^-|x)\right]-\left[\log\pi_{ref}(y^+|x)-\log\pi_{ref}(y^-|x)\right]" />

Then the logistic loss is:

<MathBlock latex="\mathcal{L}_{DPO}=-\log\sigma(\beta m)" />

The reference term says “increase the chosen-over-rejected preference relative to where the base/reference policy already was.” It is not a magic preference label, safety proof, or reward-model calibration. Sequence masks, length normalization, prompt formatting, pair quality, beta, reference checkpoint, and held-out evaluation all affect the result.

The project implements this equation over already aggregated log-probabilities and keeps the named **Stanford Rafailov et al. 2023** attribution. Its batch helper scores a causal sequence as `logits[:, :-1]` against `ids[:, 1:]`, shifts completion masks with those targets, and evaluates the reference in temporary eval/no-grad mode. It is a finite objective helper, not the data, scale, or experiment from that paper.

### KTO, IPO, ORPO, and SimPO

The family shares a preference signal but changes the estimator and reference assumptions:

| objective | local teaching shape | important design question |
| --- | --- | --- |
| DPO | reference-adjusted logistic pair margin | are the pair and reference-policy log-probs comparable? |
| KTO | bounded desirable/undesirable utility around a detached, non-negative KL estimate | are independent binary labels calibrated and balanced, and is the KL estimate representative? |
| IPO | squared target margin, commonly on token-mean scores | how does the chosen target margin and beta interact with length? |
| ORPO | SFT anchor plus the log odds-ratio term | are scores token means, and how should supervised behavior and preference pressure trade off? |
| SimPO | reference-free margin on length-normalized scores | does removing the reference increase drift or simplify tuning? |

Names do not specify every implementation detail. Report whether log-probabilities are sums or means, which tokens are masked, how ties/noise are filtered, and whether the base policy is frozen.

## 5. RLAIF and Constitutional AI

**RLAIF** replaces or supplements human preference labels with AI-generated evaluations. This can make feedback faster and broaden coverage, but it moves the burden to evaluator prompts, model choice, rubric validity, calibration, disagreement analysis, and adversarial testing. “AI feedback” is not automatically objective; it is a measurement instrument with its own bias and failure modes.

**Constitutional AI** is a family of approaches in which written principles guide critique, revision, and/or preference generation. A constitution makes values inspectable and can reduce the need to expose annotators to every harmful example. It does not make principles unambiguous, remove cultural or deployment trade-offs, or guarantee that a critic follows them. A credible report names the principles, critique/revision prompts, model versions, filtering, and human audit.

RLAIF and Constitutional AI can be combined with SFT, reward modeling, or direct preference optimization. They are not synonyms for DPO, and none is established by the toy's scalar loss. The local lab deliberately uses deterministic categorical pairs so objective plumbing does not masquerade as AI evaluation evidence.

## 6. Parameter-efficient fine-tuning

### PEFT as a systems choice

Parameter-efficient fine-tuning (PEFT) updates a small set of parameters while preserving a frozen base. Benefits can include lower optimizer memory, many task adapters per base, and a smaller artifact. Costs include adapter capacity limits, base-version compatibility, merging/dtype issues, and possible quality or safety regressions. “Fewer trainable parameters” is not equivalent to “free” or “safe.”

### LoRA

LoRA adds a low-rank update to a frozen map `W`:

<MathBlock latex="W' = W + \frac{\alpha}{r}BA,\qquad A\in\mathbb{R}^{r\times d_{in}},\quad B\in\mathbb{R}^{d_{out}\times r}" />

The forward map is `Wx + (alpha/r)BAx`. The adapter has `r(d_in+d_out)` parameters. Initializing `B=0` keeps the original function at step zero; later updates learn a task-specific direction. Which modules to target—attention query/value, output, MLP, embeddings, or all linear maps—is an experimental choice.

The project injects LoRA into named `q_proj` and `v_proj` maps, freezes and clears stale gradients from the dense base by default, preserves existing adapters when adding targets, checks the trainable count, and tests initial-logit equality. Checkpoint loading validates the injected LoRA configuration and restores saved trainability flags; load into the same adapter architecture. It does not claim to reproduce a PEFT library's sharding, merge, adapter composition, or kernels.

### QLoRA

QLoRA combines a quantized frozen base with trainable LoRA weights and a higher-precision compute path. The conceptual memory win comes from storing the base compactly while gradients flow through the adapter rather than updating quantized base weights. Real systems make decisions about quantization format, scale/statistics, dequantization kernels, optimizer paging, activation dtype, and outlier handling.

The reference project has an optional symmetric int8 round trip and a `qlora_recipe()` explanation. It intentionally does not call bitsandbytes, require CUDA, or call its helper NF4 QLoRA. A low reconstruction error on one tensor is not a throughput or quality benchmark. The local KTO baseline also reuses a labeled batch; it is an explicit approximation to the paper's mismatched-pair KL estimate, not a full trainer.

### DoRA

DoRA separates the learned magnitude from the directional update. A simplified conceptual form decomposes a weight into a magnitude and normalized direction, then applies a low-rank directional change plus a learned magnitude adjustment. This can improve the expressiveness of a low-rank adapter in some settings, but it adds parameters and initialization/merge choices. DoRA is part of the design map here, not implemented in the tiny reference project; an implementation belongs behind tests for identity, gradients, merge, dtype, and parameter counts.

## 7. Synthetic preference data and evaluator boundaries

A deterministic pair fixture is useful for a unit test, not for claiming preference quality. Synthetic preference data can be made by:

1. writing task templates and explicit rubrics;
2. generating multiple candidate responses;
3. scoring with rules, a model evaluator, or both;
4. retaining the prompt, candidates, score/reason, evaluator version, and tie;
5. auditing a sample with humans and adversarial cases; and
6. splitting by prompt/template/entity so near-duplicates do not leak.

Common artifacts include length preference, refusal-template preference, judge self-consistency, contamination, and reward hacking. Test candidates that are verbose but wrong, safe-sounding but evasive, and formatted to exploit the evaluator. A held-out evaluator or human audit is more informative than selecting the lowest training loss.

RLAIF, Constitutional AI, and synthetic-data pipelines are policy and evaluation choices around the objective. A direct preference loss cannot recover information that the pair construction never measured.

<Gotcha>A preference pair says which response won under one rubric and context. It does not say that the chosen response is true, universally safe, or better for every user. Record abstentions and annotator/evaluator disagreement.</Gotcha>

<KeyTakeaways>
- A causal LM maps token prefixes to next-token distributions; SFT is masked behavior cloning, and its loss is not a universal quality or alignment measure.
- RLHF uses a reward/evaluation model plus an RL update and reference regularization; RLAIF changes the feedback source; Constitutional AI makes principles and critique/revision part of the feedback design.
- This lesson attributes DPO to **Stanford's Rafailov et al. (2023)**. DPO's reference-adjusted log-ratio loss is direct preference optimization, not a guarantee that preference data is true or unbiased.
- KTO, IPO, ORPO, and SimPO make different choices about labels, reference policies, anchors, and margins. Name masks, causal shifting, sum versus selected-token mean, beta/gamma, KL approximation, and checkpoint whenever comparing them.
- PEFT/LoRA can reduce updated parameters; QLoRA combines a quantized frozen base with adapters; DoRA adds magnitude/direction structure. Fewer trainable parameters do not guarantee quality, safety, or lower end-to-end cost.
- Synthetic and AI feedback can scale coverage while introducing evaluator bias, verbosity/reward hacking, contamination, and principle ambiguity. Audit them with held-out prompts, adversarial slices, and human disagreement.
- The Week 15a project is an offline microscope: its finite losses, adapter identity test, and checkpoint round trip establish plumbing only. Public company evidence remains release-specific and must be separated from practice analogy.
