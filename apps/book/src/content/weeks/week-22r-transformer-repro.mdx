<Hook>What does it mean to reproduce a paper when your code runs but your data, architecture and metric are different?</Hook>
<Intuition>
Research reproduction has three levels. **Mechanism parity** means a mathematical operation matches its derivation. **Experimental parity** means the dataset, architecture, training and evaluation approximate the published experiment. **Claim replication** asks whether the evidence supports the same conclusion. Passing a tensor-shape test addresses only part of the first level.

Start with Vaswani et al. 2017, Google Brain before its merger with DeepMind. Read the abstract for the claim, figures for information flow, equations for implementation units, and appendices for training details. Build a claim → oracle → experiment → limitation table before opening an editor. This week reproduces causal attention and a small decoder mechanism, not the original WMT translation result.

## The math, derived

### Attention from a weighted sum

Queries Q and keys K have final width d. Values V may have a different final width. Dot products produce one score for each query/key pair. Scaling by square root d controls variance when dimensions contribute approximately independently. Causal masking excludes future keys **before** normalization.

<MathBlock latex="S=QK^\top/\sqrt{d},\qquad A_{ij}=\frac{\exp(S_{ij})\mathbf{1}[j\le i]}{\sum_{k\le i}\exp(S_{ik})},\qquad O=AV" />

For zero Q/K every allowed score is equal. With scalar values [1,3,8], output positions are [1,2,4]. A wrong mask can still make rows sum to one, so verify the expected prefix averages and suffix-perturbation invariance as independent tests.

### Gradient oracle

For a scalar objective f and parameter coordinate x_i, centered finite differences approximate the derivative. Compare them against autograd in float64, away from nondifferentiable boundaries.

<MathBlock latex="\frac{\partial f}{\partial x_i}\approx\frac{f(x+\epsilon e_i)-f(x-\epsilon e_i)}{2\epsilon}" />

Too large epsilon introduces approximation error; too small amplifies cancellation. PyTorch `gradcheck` manages tolerances, but the experiment still needs finite, nondegenerate inputs. Gradient parity matters because matching inference outputs does not establish a correct training implementation.

### Reproduction choices are variables

The original paper uses encoder-decoder attention, sinusoidal positions, ReLU feed-forward layers and its specified normalization/training schedule. Our one-block causal decoder uses learned positions, GELU and pre-norm. These are deliberate teaching choices, not hidden claims of architectural identity.

<MathBlock latex="h'=h+\operatorname{Attention}(\operatorname{LN}(h)),\qquad h''=h'+\operatorname{FFN}(\operatorname{LN}(h'))" />

Pre-norm places normalization before each residual branch. Compare post-norm under a controlled ablation; do not simultaneously change width, learning rate and data, then attribute the curve to normalization alone.

## The code, from scratch

```python
import torch
from transformer_repro import attention, train_fixture

q = torch.zeros(1, 3, 4)
v = torch.tensor([[[1.0], [3.0], [8.0]]])
out, weights = attention(q, q, v)
torch.testing.assert_close(out[..., 0], torch.tensor([[1.0, 2.0, 4.0]]))
curve = train_fixture(seed=22, steps=30)
assert curve[-1] < curve[0]
```

The public API also includes `TinyTransformer` and `causal_batch`. Each input window excludes its last token; each label window excludes its first. The notebook compares three seeds without changing global RNG state outside the training helper. Checkpoint tests hold architecture fixed; a real release needs constructor, vocabulary and tokenizer metadata too.

### A paper-reading and reporting protocol

1. Write one falsifiable claim and name the exact figure/table/equation supporting it.
2. List data, optimizer, architecture, compute, metric and sampling assumptions.
3. Implement the smallest unit with an independent oracle and a failing regression.
4. Run a seeded baseline, preserve raw artifacts, then one ablation.
5. Report uncertainty, failed runs, deviations and what your experiment cannot establish.

A four-page report can use: question and source claim; implementation/protocol; results plus ablation; limitations and extension. Do not hide adverse seeds or tune on the final holdout. The companion [paper-reading protocol](/paper-reading-protocol) and [technical writing guide](/tech-writing) supply the reading/writeup workflow.

<KeyTakeaways>
- Define the level of reproduction before writing code.
- Independent analytic and gradient oracles catch different bugs.
- State every architectural deviation.
- Preserve failed runs and negative results.
- A small, honest experiment is stronger than an unsupported frontier claim.
</KeyTakeaways>
