<Hook>How can a model read one character at a time without forcing every useful detail through one final hidden state?</Hook>

<Intuition>
A recurrent neural network reuses the same transition at every position in a sequence. For a character model, an embedding turns the current character into a vector, a recurrent cell combines it with a state carried from the past, and a vocabulary head scores the next character. This gives the model a variable-length computation without changing its parameter count when the text gets longer.

<IntuitionCallout>An LSTM gives the state a controlled memory lane; a GRU combines the same idea into fewer gates. Additive attention then lets each decoder step retrieve a weighted summary of *all* encoder states instead of trusting one compressed final state.</IntuitionCallout>

This week has five moves: unroll a vanilla RNN, make long-term memory explicit with LSTM and GRU gates, separate reading from writing with a character-level seq2seq model, derive additive attention as a learned soft lookup, and train the whole contract with a deterministic in-memory fixture. The reference project uses PyTorch on CPU and never downloads Shakespeare or any other corpus.

## The anatomy of a character-level recurrent model

Let a batch contain `B` sequences of length `T`, vocabulary size `V`, embedding width `E`, and hidden width `H`. Integer character ids have shape `(B, T)`. An embedding lookup produces `X` with shape `(B, T, E)`. The recurrent stack emits one state per input position, `(B, T, H)`, and a vocabulary head maps each state to logits `(B, T, V)`.

A next-character fixture uses two aligned windows:

```text
source x = text[t : t + T]
target y = text[t + 1 : t + T + 1]
```

The target is not the source copied unchanged. It is the source shifted by one character, which makes every row a supervised prediction problem. The reference `TinyCharDataset` keeps these windows in memory, sorts its character vocabulary deterministically, and returns `torch.long` ids.

### 1. The vanilla RNN recurrence

For one step, let `x_t` be the embedding and `h_{t-1}` the previous hidden state:

<MathBlock latex="h_t = \tanh(W_x x_t + W_h h_{t-1} + b_h),\qquad z_t = W_o h_t + b_o,\qquad p(y_t\mid x_{\leq t}) = \operatorname{softmax}(z_t)" />

The same `W_x`, `W_h`, and `W_o` are reused for every `t`. Unrolling gives a causal model: position `t` can depend on the prefix through `h_t`, but not on future characters. The hidden state is useful precisely because it carries information forward; it is also a bottleneck because all earlier evidence has to survive repeated nonlinear transitions.

Backpropagation through time applies the chain rule through every transition. If the recurrent Jacobian has a norm below one, gradients can vanish across long spans; if it is above one, they can explode. This is an optimization property of the unrolled computation, not a statement that one RNN architecture is universally bad. Initializing the experiment, checking the target shift, clipping a gradient, and inspecting loss are more useful first steps than immediately increasing model size.

### 2. LSTM anatomy: a controlled cell state

An LSTM keeps a cell state `c_t` in addition to its exposed hidden state `h_t`. With `u_t = [h_{t-1}; x_t]`, its gates are:

<MathBlock latex="i_t = \sigma(W_i u_t+b_i),\quad f_t=\sigma(W_f u_t+b_f),\quad o_t=\sigma(W_o u_t+b_o),\quad g_t=\tanh(W_g u_t+b_g)" />

The candidate `g_t` is written through the input gate, old memory is retained through the forget gate, and the output gate controls what the rest of the network sees:

<MathBlock latex="c_t = f_t \odot c_{t-1} + i_t \odot g_t,\qquad h_t=o_t\odot\tanh(c_t)" />

The addition in `c_t` creates a relatively direct derivative path. The derivative with respect to the old cell state contains the forget gate, `∂c_t/∂c_{t-1} = f_t`, rather than only a fresh matrix multiplication and saturating nonlinearity. Gates can still forget information, and exploding gradients are still possible, so the cell state is an optimization aid rather than a guarantee.

### 3. GRU anatomy: fewer pieces, same recurrent contract

A GRU does not keep a separate cell state. Its update gate `z_t` controls how much old state survives, while its reset gate `r_t` controls how much old state enters a candidate:

<MathBlock latex="z_t=\sigma(W_zx_t+U_zh_{t-1}+b_z),\qquad r_t=\sigma(W_rx_t+U_rh_{t-1}+b_r)" />

One common convention writes the candidate and interpolation as:

<MathBlock latex="\tilde h_t=\tanh(W_hx_t+U_h(r_t\odot h_{t-1})+b_h),\qquad h_t=(1-z_t)\odot h_{t-1}+z_t\odot\tilde h_t" />

Implementations differ in the exact placement of the reset gate, so equations should be matched to the library's documented convention. The important interface is the same: a sequence of embeddings becomes one hidden vector per position. The project exposes both `CharLSTMAttention` and `CharGRUAttention`; either can feed the same additive-attention module and vocabulary head.

<Gotcha>A GRU is not an LSTM with a cell-state tensor renamed. Compare parameter counts, gate conventions, and the returned state when writing a baseline. Test the public shape contract instead of assuming two recurrent modules expose identical internals.</Gotcha>

## Seq2seq: separate the encoder from the decoder

A sequence-to-sequence model makes the source/target distinction explicit. An encoder reads `x_1, ..., x_S` and emits states `h_1, ..., h_S`. A decoder predicts `y_1, ..., y_T` conditional on the encoded source and its own previous outputs:

<MathBlock latex="p(y_{1:T}\mid x_{1:S}) = \prod_{t=1}^{T}p(y_t\mid y_{<t}, x_{1:S})" />

The reference character task uses overlapping next-character windows, so `S` and `T` are often equal, but the model keeps the more general `(B, S)` source and `(B, T)` target contract. A tiny deterministic first source token acts as a BOS input. A production tokenizer would add explicit BOS and EOS symbols and decide how to handle padding.

During teacher-forced training, the decoder input at step `t` is the gold `y_{t-1}`. With a one-token BOS, the decoder input sequence is `[BOS, y_1, ..., y_{T-1}]`, and the logits are compared with `[y_1, ..., y_T]`. Teacher forcing gives a clean parallel training pass, but it means training inputs are more reliable than the model's own predictions.

During free-running generation, the model samples or chooses `\hat y_t` and feeds it back as the next input. A falling teacher-forced loss is therefore not proof of good long-horizon text. The project exposes `teacher_forcing_ratio=0` for free-running decoder steps and intermediate ratios for a controlled mixed experiment; generation records its prompt, seed, temperature, and checkpoint rather than cherry-picking a sample.

## Additive attention: derive the soft lookup

A decoder that sees only the encoder's final state asks that one vector to remember every source detail. Attention keeps the whole sequence of encoder states available. For decoder query `q_t` and encoder state `h_s`, project both into an attention space of width `A`, add them, apply a nonlinearity, and score:

<MathBlock latex="e_{t,s}=v_a^{\mathsf T}\tanh(W_q q_t+W_h h_s+b_a)" />

For every fixed decoder step `t`, normalize scores over source time `s`:

<MathBlock latex="\alpha_{t,s}=\frac{\exp(e_{t,s})}{\sum_{j=1}^{S}\exp(e_{t,j})},\qquad \sum_{s=1}^{S}\alpha_{t,s}=1" />

The context is the weighted sum of encoder values:

<MathBlock latex="c_t=\sum_{s=1}^{S}\alpha_{t,s}h_s,\qquad \text{logits}_t=W_o[q_t;c_t]+b_o" />

With a batch, decoder queries are `(B, T, H)`, encoder values are `(B, S, H)`, energies and weights are `(B, T, S)`, and contexts are `(B, T, H)`. The score is *additive* because projected query and value vectors are added before `tanh`; it is not scaled dot-product attention. A source mask sets padded energies to a large negative value before softmax, so invalid positions receive zero probability while valid positions still sum to one.

The training objective is token cross-entropy. For target id `y_t` and vocabulary logits `z_t`:

<MathBlock latex="\ell_t=-\log\operatorname{softmax}(z_t)_{y_t},\qquad L_{mean}=\frac{1}{BT}\sum_{b=1}^{B}\sum_{t=1}^{T}\ell_{b,t}" />

The project keeps `none`, `sum`, and `mean` reductions visible. That makes it possible to inspect difficult positions, prove the reduction identity, and compare loss values without confusing a larger token count with a better model. Backpropagation sends gradients through the vocabulary head, context sum, softmax weights, attention score network, recurrent states, and embeddings.

## The code, offline and inspectable

```python
import torch
from torch.utils.data import DataLoader

from char_rnn_attention import CharLSTMAttention, make_tiny_dataset
from char_rnn_attention.train import fit

torch.manual_seed(7)
dataset = make_tiny_dataset(seq_len=24, repeats=2)
model = CharLSTMAttention(
    dataset.vocab.size,
    embedding_size=24,
    hidden_size=32,
    attention_size=40,
)
history = fit(
    model,
    DataLoader(dataset, batch_size=32, shuffle=False),
    torch.optim.Adam(model.parameters(), lr=3e-3),
    epochs=3,
)
print(history['loss'])
print(model.generate(dataset.vocab, 're', max_new_tokens=40, temperature=0.0))
```

<KeyTakeaways>
- A vanilla RNN reuses one transition across time; its hidden state is a causal summary but can create long gradient paths.
- LSTM gates regulate a separate additive cell state, while GRU update/reset gates provide a smaller recurrent state contract.
- Seq2seq factorizes conditional sequence likelihood; teacher forcing trains with gold history, while generation feeds back predictions.
- Additive attention scores every decoder-query/source-state pair, normalizes over source time, and returns a weighted context.
- Deterministic CPU/offline tests can validate shapes, masks, finite gradients, reductions, and loss movement; they cannot establish Shakespeare quality or any company's private architecture.
</KeyTakeaways>
