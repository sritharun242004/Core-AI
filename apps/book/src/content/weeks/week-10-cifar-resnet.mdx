<Hook>What if a deeper vision model could learn new features without having to relearn the identity function at every layer?</Hook>

<Intuition>
A convolutional network is a sequence of small, shared detectors. Early filters can respond to edges and colour contrasts; later filters combine those responses into textures, parts, and class evidence. Sharing a kernel across positions gives a useful inductive bias: a cat ear is still an edge-and-texture pattern when it moves across the image.

<IntuitionCallout>A residual block does not demand that every new layer invent a complete representation. It learns a correction `F(x)` and adds it to a route that already carries `x`: `y = ReLU(F(x) + S(x))`. If the correction is not useful, the identity route is still available.</IntuitionCallout>

This week has four moves: turn local patches into feature maps, preserve signal with identity or projection skips, perturb only the training view with augmentation, and reuse a learned backbone while replacing the task-specific head. The project keeps these contracts visible in small PyTorch modules and CPU/offline tests.

## The math, derived

### 1. A convolution is shared local correlation

For a one-channel input `X` and kernel `K`, a valid cross-correlation at output location `(i,j)` is:

<MathBlock latex="Y_{i,j} = b + \sum_{u=0}^{K_h-1}\sum_{v=0}^{K_w-1} K_{u,v}X_{i+u,j+v}" />

Deep-learning libraries call this operation convolution even though they usually do not reverse the kernel. With `C_in` input channels and `C_out` filters, each output channel has a kernel for every input channel. Padding `P` and stride `S` determine the spatial output:

<MathBlock latex="H_{out}=\left\lfloor\frac{H+2P-K_h}{S}\right\rfloor+1,\qquad W_{out}=\left\lfloor\frac{W+2P-K_w}{S}\right\rfloor+1" />

A 3×3 kernel with padding 1 and stride 1 preserves a 32×32 CIFAR image. A stride-2 stage approximately halves it while increasing channel capacity. Batch normalization then standardizes each channel during training, and ReLU supplies a piecewise-linear gate:

<MathBlock latex="\operatorname{ReLU}(z)=\max(0,z),\qquad \frac{\partial\operatorname{ReLU}}{\partial z}=\mathbf{1}[z>0]" />

The receptive field grows as layers compose: a later unit can combine nearby edges into a shape, while shared weights make the detector translation-tolerant rather than position-specific.

### 2. Why residual addition changes optimization

A plain block asks its layers to learn `H(x)`. A residual block writes `H(x)=F(x)+x` when shapes match:

<MathBlock latex="y=\operatorname{ReLU}(F(x)+S(x)),\qquad S(x)=x\ \text{or}\ P_s x" />

Before the final gate, the derivative with respect to the input contains a direct route:

<MathBlock latex="\frac{\partial L}{\partial x}=\frac{\partial L}{\partial y}\left(\frac{\partial F}{\partial x}+\frac{\partial S}{\partial x}\right),\qquad \frac{\partial S}{\partial x}=I\ \text{for an identity skip}" />

The identity term does not guarantee a non-vanishing gradient after every operation, but it gives optimization a useful baseline. When a stage changes from `(B,C,H,W)` to `(B,C',H/2,W/2)`, `S` is a 1×1 convolution with stride 2 plus normalization, so both branches land at the same shape before addition. The reference `BasicBlock` tests both cases and backpropagates a real loss through them.

### 3. Augmentation estimates an invariance prior

Let `T` be a random transform sampled from an augmentation distribution `q(T)`. Training minimizes an expected loss over transformed views:

<MathBlock latex="\min_\theta\ \mathbb{E}_{(x,y)\sim D}\,\mathbb{E}_{T\sim q}\left[-\log p_\theta(y\mid T(x))\right]" />

Random crop and horizontal flip are useful when the label remains unchanged under those transformations. Padding before cropping changes framing without inventing pixels at the border of the original image. The project passes a seeded `torch.Generator` into its tensor-only transform so this expectation is testable without a global RNG or a network dataset.

Augmentation is not a free accuracy button. An upside-down digit, a mirrored traffic sign, or a medical laterality cue may change the label. The deployment distribution—not convention—decides whether a transformation is valid.

### 4. Transfer learning is constrained adaptation

Suppose a backbone `f_\phi` maps pixels to features and a new head `g_\psi` maps features to task labels. A frozen-backbone run optimizes:

<MathBlock latex="\min_\psi\ \frac{1}{n}\sum_{i=1}^{n}\ell\left(g_\psi(f_{\phi_0}(x_i)),y_i\right),\qquad \phi=\phi_0" />

Freezing reduces trainable parameters and preserves a useful representation when the new data is small or related. Unfreezing the last stage allows controlled adaptation, usually with a smaller learning rate than the fresh head. The code's `replace_classifier` and `freeze_backbone` make the parameter boundary inspectable; BatchNorm running statistics still need an explicit train/eval policy.

<Gotcha>Accuracy is not a property of “ResNet” in the abstract. The result depends on data split, normalization, augmentation, schedule, seed, device, and training time. The offline fixture proves plumbing, not CIFAR-10 performance; roughly 90% locally on MPS is realistic for a careful run, while 93%+ generally needs cloud/MLX time.</Gotcha>

## The code, from scratch

```python
from torch.utils.data import DataLoader

from cifar_resnet import CIFARTrainTransform, make_fake_cifar, resnet18
from cifar_resnet.train import fit

# This is deterministic, in-memory, CIFAR-shaped data — not a CIFAR benchmark.
train = make_fake_cifar(128, seed=7, transform=CIFARTrainTransform(padding=2))
model = resnet18(num_classes=10, widths=(8, 16, 32, 64), blocks=(1, 1, 1, 1))
history = fit(
    model,
    DataLoader(train, batch_size=32, shuffle=False),
    epochs=2,
    learning_rate=0.02,
    device='cpu',
)
print(history['train_loss'][-1])
```

<KeyTakeaways>
- Convolutions trade dense connectivity for local receptive fields and shared weights; padding and stride determine every feature-map shape.
- A residual block learns a correction beside an identity or projection route, making shape alignment and gradient flow explicit.
- Augmentation optimizes expected loss over transformed training views; it is valid only when the transform preserves the deployment label.
- Transfer learning freezes or gently adapts a backbone while a new head learns the task; BatchNorm state needs an explicit policy.
- Deterministic CPU/offline tests validate model plumbing, not CIFAR accuracy. Roughly 90% on local MPS is realistic with a careful run; 93%+ generally needs cloud/MLX resources.
</KeyTakeaways>
