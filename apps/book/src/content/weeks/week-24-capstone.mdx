## The math, derived

### Score evidence, then apply hard gates

Each track has five criteria scored 0–20. Add them for a 100-point self-assessment; release gates such as objective correctness, absence of leakage and safe handling of secrets cannot be compensated for by good documentation.

<MathBlock latex="S=\sum_{j=1}^{5}s_j,\quad 0\le s_j\le20,\qquad \mathrm{ready}=\mathbf{1}[S\ge80]\prod_k\mathbf{1}[g_k\ \mathrm{passes}]" />

Worked example: [18,16,17,19,12] totals 82. If the evaluation leaks future labels, the artifact is not ready despite that number. The 80-point guideline is a study target, not an employer hiring threshold.

### Pair quality with cost

Measure baseline and candidate on identical held-out cases, report uncertainty and choose the operational constraint before seeing the winner. For a serving project, throughput, latency and dollar cost have explicit denominators; for research, parameter count and token exposure are not interchangeable with measured GPU-hours.

<MathBlock latex="\Delta=\frac{1}{n}\sum_i(s_i^{\mathrm{candidate}}-s_i^{\mathrm{baseline}}),\qquad \mathrm{cost/task}=\frac{\mathrm{total\ measured\ cost}}{\mathrm{completed\ tasks}}" />

A system that completes only easy tasks can artificially lower average cost per completed task. Also report attempt counts, failure rate, retry cost and task slices. Use Week 20's paired evaluation discipline rather than inventing a new favorable metric after results arrive.

## The code, from scratch

Your capstone code is deliberately **not supplied**: building it is the assessment. The repository supplies complete rubrics and a deliverable contract, not an empty application disguised as a finished solution.

```text
capstone/track-<role>/<your-project>/
  README.md       # setup, one-command run, known limits
  WRITEUP.md      # claim, method, protocol, results, limitations
  DEMO.md         # ordinary path + error path + measured evidence
  COMPUTE.md      # budget, stop conditions, teardown
  SELF_RUBRIC.md  # criterion -> evidence -> points -> deductions
  src/
  tests/
  evals/
  configs/
  notebooks/
```

### Research engineering

Choose mini-Chinchilla, verifier-based mini-GRPO, dense versus sparse MoE at matched active parameters, or test-time-compute scaling. Deliver correctness oracles, a baseline, ablations, seed-level uncertainty and a four-page report with one justified extension. Do not turn synthetic fixture slopes into frontier scaling claims. Rubric: `capstone/track-research/RUBRIC.md`.

### Applied ML

Choose a four-stage MovieLens recommender, fraud GNN+GBM comparison, ad-ranking/A-B simulator, or hierarchical forecasting study. Deliver temporal/entity splits, production-shaped transforms, strong simple baselines, measured local latency/cost and honest experiment assumptions. A simulated A/B lift is not a deployed causal result. Rubric: `capstone/track-applied-ml/RUBRIC.md`.

### LLM product / agentic

Choose citation-backed research, bounded code review, a domain fine-tune+RAG hybrid or voice-native interaction. Deliver a real usable interface, task/regression/red-team evaluations, bounded tools, failure recovery and measured latency/cost. A mock protocol exchange is not a standards-compliant deployed service. Rubric: `capstone/track-llm-product/RUBRIC.md`.

### Seven work sessions

| Session | Output | Stop condition |
|---|---|---|
| D1 | Scope, question, baseline, non-goals and license/budget | Cannot name a decisive metric |
| D2–3 | Architecture, data contract and failing acceptance tests | No reproducible baseline |
| D4–5 | Core implementation and raw artifacts | Unbounded scope or compute spend |
| D6 | Holdouts, ablations, failure review and polish | Known correctness/leakage/safety violation |
| D7 | Writeup, demo, clean reproduction and self-score | Claim has no linked evidence |

<Assignments>
- **Warmup (30 min):** write a one-paragraph question, baseline, metric and non-goals.
- **Build (2–3 hrs):** create the skeleton and one failing acceptance test before adding features.
- **Challenge (3+ hrs):** have a peer or a fresh environment reproduce the claim and record every failure.
</Assignments>
<InterviewDrill role="research-eng" time="30 min">
**“Walk through your project, then tell me why its headline result might be wrong.”**

Baseline: explain inputs, method and output. Senior: defend baselines, splits and tests. Staff: discuss uncertainty, limitations, operational risks and the next discriminating experiment. Worked rubric: `capstone/README.md` and your chosen track's `RUBRIC.md`.
</InterviewDrill>

<KeyTakeaways>
- Choose one role and one falsifiable problem.
- Link every claim to reproducible evidence.
- Hard correctness and safety gates override an aggregate score.
- Budget real time for evaluation and writeup.
- A capstone demonstrates judgment, not a guaranteed hiring outcome.
</KeyTakeaways>
