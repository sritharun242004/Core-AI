## The math, derived

### 1. Define the unit of evaluation

For binary case outcomes y_i, accuracy is their mean. A task with ten repeated trajectories is not ten independent tasks. If you want task-level generalization, aggregate or cluster at the task level before constructing uncertainty intervals.

<MathBlock latex="\hat p=\frac{1}{n}\sum_{i=1}^{n}y_i,\qquad d_i=s_i^{\mathrm{candidate}}-s_i^{\mathrm{baseline}},\qquad \bar d=\frac{1}{n}\sum_i d_i" />

Worked example: baseline [0,1,1,0] and candidate [1,1,0,1] give differences [1,0,-1,1], mean .25. That means one more correct answer out of four, not a robust deployment improvement. Inspect the newly broken case, not just the mean.

### 2. Bootstrap paired differences

Draw n case indices with replacement, compute a bootstrap mean, and repeat B times. Use percentile endpoints for an illustrative interval. The implementation uses a seeded NumPy generator and resamples **differences**, preserving the within-case pairing.

<MathBlock latex="\bar d^{*(b)}=\frac{1}{n}\sum_{j=1}^{n}d_{I_j^{(b)}},\quad I_j^{(b)}\sim\operatorname{Uniform}\{1,\ldots,n\}" />

The local gate requires the lower 95% percentile endpoint to exceed negative allowed regression. This is a policy choice, not a universal hypothesis test. Small datasets, dependent observations, adaptive threshold tuning and many simultaneous comparisons all weaken simple interval interpretations. Freeze the policy on validation, then evaluate once on the final test set.

### 3. A judge is another model under test

A model judge can prefer long answers, its own style, or the first answer shown. Ask the same rubric with A/B and B/A order, map both votes back to the original candidate, and retain disagreement. A left-biased judge yields 1 then 0: its average is .5, but that is not an agreed tie.

<MathBlock latex="s_A=\frac{v(A,B)+1-v(B,A)}{2},\qquad \mathrm{agreement}=\mathbf{1}[v(A,B)=1-v(B,A)]" />

Here v is 1 for left wins, 0 for right wins and .5 for tie. Calibrate against independently labeled human examples; track preference, factual correctness and task success separately. Candidate text is untrusted data and may contain instructions targeting the judge. JSON schema validation prevents malformed outputs from becoming silent passes, but does not solve semantic prompt injection.

### 4. Drift is a signal, not a verdict

Fit reference histogram bins once, including open-ended tails. For reference fractions p and current fractions q, the population stability index is:

<MathBlock latex="\operatorname{PSI}(p,q)=\sum_b(q_b-p_b)\log\frac{q_b}{p_b}" />

Add small pseudocounts and renormalize to avoid zero divisions. Refitting bins on each current batch can hide movement; dropping out-of-range values can hide the largest shift. PSI on features cannot prove concept drift in labels conditional on features. Constant reference features deserve an explicit change-of-value monitor rather than blind trust in quantile bins.

### 5. Contamination and provenance

The n-gram diagnostic reports the fraction of distinct evaluation-prompt n-grams found in training prompts with other IDs. It detects some copied text, misses paraphrases, and flags innocent templates. Unknown pretraining data cannot be certified clean by a local overlap check. Synthetic data needs generator/model/rubric provenance and duplicate filtering **before** splitting; distillation can transfer training contamination too.

<Gotcha>A release gate cannot repair a leaked test set. Repeatedly tune prompts against the same final benchmark and it becomes development data, whatever filename you give it.</Gotcha>

### From notebook to operations

Data pipelines validate schema, deduplicate and freeze approved datasets. Feature stores add point-in-time correctness: join a value as known **at prediction time**, not a later correction. Offline and online transforms must agree. CI runs small offline regressions; larger evaluation jobs use bounded queues, retries and budgets. A release progresses through shadow traffic, a canary and monitored rollout, with a known rollback artifact.

MLflow records experiments and artifacts; DVC versions data through content metadata; W&B supports tracking and visualization. They do not automatically prevent leakage or choose the right metric. The project provides a lazy local-MLflow export and an optional Inspect task constructor; DVC and offline-W&B instructions are in its README. External integrations were not installed or executed for correctness validation.

Monitor latency, cost, input shifts, task success, refusal/overrefusal and delayed outcome labels. Alert ownership and response playbooks matter more than a wall of charts. Never log credentials or sensitive prompts by default. Compare drift by important slices and pair operational signals with human review.

### Know what each named evaluation means

| Evaluation/tool | Useful question | Boundary |
|---|---|---|
| MT-Bench | How does a judge compare multi-turn responses? | Judge bias and prompt/data versions matter. |
| HELM | How do models compare across scenarios and metrics? | Broad coverage is not your product acceptance suite. |
| MMLU-Pro | How well does the model answer harder knowledge/reasoning questions? | Multiple-choice success is not tool competence. |
| SWE-Bench / Verified | Can a system resolve repository issues under tests? | Isolation, patches, test harness and contamination matter. |
| Inspect AI | How can tasks, solvers and scorers be organized? | UK AI Security Institute tooling, not a benchmark score itself. |
| Harbor | How can agent tasks run in controlled environments? | Environment fidelity and security remain your responsibility. |

An agent can complete a task after attempting an unsafe tool call. Record task success, **safe success**, tool calls, retries, cost and wall-clock separately. A trajectory review should reconstruct decisions without granting untrusted logged text authority over the evaluator.

<KeyTakeaways>
- Version every input to an evaluation claim.
- Pair observations and match uncertainty to the sampling unit.
- Treat judges as fallible models that require calibration.
- Drift/overlap diagnostics are not automatic verdicts.
- Deployment decisions require failure review, budgets and rollback ownership.
