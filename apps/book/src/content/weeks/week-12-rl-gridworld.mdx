<Hook>How do we update a policy when the target is delayed reward rather than a labeled answer?</Hook>

<Intuition>
An optimizer decides how a parameter moves after a gradient has been measured. SGD takes a step in the negative-gradient direction; Adam keeps moving averages of gradient and squared-gradient magnitudes; AdamW separates weight decay from the adaptive step. These rules solve supervised objectives well, but reinforcement learning changes the source of the learning signal: an action changes the future state, and the reward may arrive much later.

<IntuitionCallout>A gridworld is a microscope for credit assignment. Q-learning writes a Bellman target into a table, while a policy-gradient method nudges the probability of the sampled action in proportion to its return. Same environment, different object being estimated.</IntuitionCallout>

This week has five moves: derive optimization and regularization updates, state a Markov decision process precisely, implement a terminal-aware Bellman backup, derive REINFORCE from log-probabilities and discounted returns, and inspect PPO's clipped objective without pretending that one equation is a complete trainer. The reference project stays deterministic and CPU/offline: a 4×4 gridworld, a tabular Q learner, a small one-hot policy, and an executable PPO-Clip algebra demo.

## The anatomy of learning from an environment

A supervised example supplies `(x, y)` and a direct loss. An RL interaction supplies an observation or state `s_t`, an action `a_t`, a reward `r_{t+1}`, and a next state `s_{t+1}`. The agent is trying to maximize expected discounted return:

<MathBlock latex="G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty}\gamma^k r_{t+k+1},\qquad 0\leq\gamma\leq1" />

Discounting makes a far-away reward count less and makes an infinite-horizon objective finite when rewards are bounded. In the project, a small step penalty prefers short routes and the goal reward ends an episode. The map is not a benchmark: it is a controlled object for checking transitions, updates, normalization, and policy improvement.

### 1. SGD, Adam, and AdamW

For parameters `\\theta`, objective `L(\\theta)`, gradient `g_t = \\nabla_\\theta L`, and learning rate `\\eta`, vanilla stochastic gradient descent is:

<MathBlock latex="g_t=\nabla_\theta L_t(\theta_t),\qquad \theta_{t+1}=\theta_t-\eta g_t" />

SGD has one state per parameter: the parameter itself. Momentum adds a low-pass filtered direction. Adam keeps two filtered moments, correcting their initial bias:

<MathBlock latex="m_t=\beta_1m_{t-1}+(1-\beta_1)g_t,\quad v_t=\beta_2v_{t-1}+(1-\beta_2)g_t^2" />

<MathBlock latex="\hat m_t=\frac{m_t}{1-\beta_1^t},\quad \hat v_t=\frac{v_t}{1-\beta_2^t},\quad \theta_{t+1}=\theta_t-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}" />

Adam adapts the effective step to a parameter's recent gradient scale. That can be useful when policy logits or network layers receive very different signals, but the optimizer does not repair an incorrect reward, state encoding, or terminal flag.

AdamW decouples weight decay from the adaptive gradient update:

<MathBlock latex="\theta_{t+1}=(1-\eta\lambda)\theta_t-\eta\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}" />

The distinction matters. Passing `weight_decay` to AdamW is not the same operation as adding a penalty to `L` and then using Adam. The reference project exposes SGD, Adam, and AdamW by name so an ablation can state which update was actually used.

### 2. Regularization: constrain the objective, not the story

Coupled L2 adds a squared-parameter penalty:

<MathBlock latex="L_{total}=L_{data}+\lambda\sum_i\theta_i^2,\qquad \frac{\partial L_{total}}{\partial\theta_i}=\frac{\partial L_{data}}{\partial\theta_i}+2\lambda\theta_i" />

L1 instead adds `\\lambda\\sum_i|\\theta_i|` and has a sign subgradient away from zero. Both encode a preference for smaller parameters, but neither guarantees better reward or generalization. In a policy, regularization can also reduce the ability to represent a sharply preferred action, so report the coefficient and the policy entropy rather than only the final return.

<Gotcha>Do not casually combine an L2 term, optimizer weight decay, and entropy regularization, then call the result “Adam.” They affect different parts of the update. Name every term and record whether it was applied to policy logits, a value baseline, or both.</Gotcha>

## MDPs and tabular control

A finite Markov decision process is `(S, A, P, R, \\gamma)`. `P(s'|s,a)` describes the next-state distribution and `R(s,a,s')` the reward. The Markov property says that the current state contains the information needed for the next transition; the history used to reach `s_t` is not required. The reference gridworld encodes `(x,y)` as `s=y\\,width+x`, has four actions, and makes `P` deterministic. Its transition table is therefore directly inspectable.

The state-value and action-value functions are:

<MathBlock latex="V^\pi(s)=\mathbb{E}_\pi[G_t\mid s_t=s],\qquad Q^\pi(s,a)=\mathbb{E}_\pi[G_t\mid s_t=s,a_t=a]" />

For a fixed policy, the Bellman expectation equation averages over its next action. For control, Q-learning uses the greedy Bellman optimality target:

<MathBlock latex="y_t=r_{t+1}+\gamma(1-d_t)\max_{a'}Q(s_{t+1},a'),\qquad Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha\big[y_t-Q(s_t,a_t)\big]" />

Here `d_t` is one only for a true terminal transition. A goal transition must not bootstrap from the goal's outgoing row. The project makes the goal row absorbing for the model table and separately records `terminated` versus `truncated` in `step()`; that distinction prevents a time limit from accidentally becoming a terminal reward boundary.

The behavior policy is epsilon-greedy:

<MathBlock latex="a_t=\begin{cases}\text{random action},&\text{with probability }\epsilon\\\arg\max_a Q(s_t,a),&\text{otherwise.}\end{cases}" />

Exploration is not the same as evaluation. Training samples exploratory actions; evaluation uses the greedy table and reports both mean return and goal success. On this known map, those numbers verify that the learned route improved. They do not measure transfer to an unseen map.

## Policy gradients: optimize probabilities directly

A stochastic policy emits logits `z_\\theta(s)` and a normalized distribution:

<MathBlock latex="\pi_\theta(a\mid s)=\operatorname{softmax}(z_\theta(s))_a=\frac{\exp z_{\theta,a}(s)}{\sum_b\exp z_{\theta,b}(s)}" />

For a sampled trajectory, the probability of the action sequence is the product of action probabilities. Products are awkward numerically, so take logs:

<MathBlock latex="\log p_\theta(\tau)=\sum_t\log\pi_\theta(a_t\mid s_t)" />

The log-derivative identity gives the policy-gradient estimator:

<MathBlock latex="\nabla_\theta J(\theta)=\mathbb{E}\left[\sum_t G_t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\right]" />

To use a minimization optimizer, negate it:

<MathBlock latex="L_{REINFORCE}=-\frac{1}{T}\sum_{t=0}^{T-1}G_t\log\pi_\theta(a_t\mid s_t)" />

A positive return makes the selected action more likely; a negative return makes it less likely. This is a high-variance estimate because one sampled trajectory carries the credit signal. Standardizing returns can improve numerical conditioning without changing the policy probabilities. An entropy bonus preserves exploration:

<MathBlock latex="L=L_{REINFORCE}-\beta\,\mathbb{E}_s[H(\pi_\theta(\cdot\mid s))],\qquad H(\pi)=-\sum_a\pi(a)\log\pi(a)" />

The baseline policy uses one-hot state features, so every probability row can be inspected. Its `softmax` is normalized over actions, not states, batch items, or hidden features. A finite gradient confirms the computation graph; a rising success rate under a fixed greedy evaluation is stronger evidence that the update is useful on this fixture.

## PPO-Clip as a conceptual bridge

Policy gradients can change a policy too aggressively when a high-return sample receives a large update. PPO compares the new policy to a frozen old policy at the sampled action:

<MathBlock latex="r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)}=\exp\left(\log\pi_\theta-\log\pi_{old}\right)" />

With an advantage estimate `A_t`, the clipped surrogate is:

<MathBlock latex="L^{CLIP}_t=\min\left(r_tA_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t\right)" />

For a positive advantage, increasing a ratio above `1+\\epsilon` no longer earns a larger surrogate contribution. For a negative advantage, pushing the ratio below `1-\\epsilon` no longer improves the objective. The sign must be multiplied before the minimum; clipping a ratio without its advantage is not PPO's objective.

The project implements `ppo_clip_demo` and tests this algebra with fixed old/new log-probabilities. It is deliberately labeled conceptual: a complete PPO system also needs rollout collection, a value function, advantage estimation, minibatch epochs, and stability diagnostics. Keeping the clip term standalone makes the policy-update boundary easy to derive and test without claiming a benchmark.

<KeyTakeaways>
- SGD, Adam, and AdamW differ in optimizer state and in how regularization enters the parameter update; record the exact choice.
- An MDP makes state, action, transition, reward, and discount explicit; terminal flags determine whether a Bellman target may bootstrap.
- Q-learning estimates action values with a greedy Bellman target, while REINFORCE changes action probabilities using sampled discounted returns.
- Softmax probabilities must normalize over actions, and entropy or return standardization changes the learning dynamics without changing the MDP.
- PPO-Clip limits the signed surrogate contribution relative to an old policy; an executable clip demo is not a complete PPO trainer or a production claim.
</KeyTakeaways>
