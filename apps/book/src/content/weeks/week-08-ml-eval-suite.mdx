<Intuition>
Evaluation is an experimental design problem. Your model is one participant; the split, metric, and data-collection timeline are the laboratory. If information crosses the boundary from future or test rows into training, the model can look brilliant without learning a reusable rule.

<IntuitionCallout>
The safest evaluation pipeline makes the honest path the easiest path: put preprocessing inside the fold, keep a final holdout untouched, and return the whole curve—not just the best number.
</IntuitionCallout>

The four moves are: choose a split that matches deployment, separate bias from variance with learning curves, check probability calibration, and search for target leakage before celebrating a score.

## The math, derived

### 1. Splits estimate different things

Let `D` be the observed dataset. A training set estimates parameters, a validation set chooses among experiments, and a final test set estimates performance on an untouched sample. In `k`-fold cross-validation, each fold takes a turn as validation:

<MathBlock latex="\widehat{M}_{CV} = \frac{1}{k}\sum_{j=1}^{k} M(f_{-j}, D_j)" />

Here `f_{-j}` is trained without fold `j`, and `D_j` is the held-out fold. The mean estimates performance; the spread communicates how sensitive the result is to the split.

### 2. Bias and variance

Expected test error can be decomposed at an input `x` into irreducible noise, squared bias, and variance:

<MathBlock latex="\mathbb{E}[(Y-\hat f(x))^2] = \sigma^2 + \big(\mathbb{E}[\hat f(x)]-f(x)\big)^2 + \mathbb{E}\big[(\hat f(x)-\mathbb{E}[\hat f(x)])^2\big]" />

A learning curve makes the trade-off visible. High training and validation error suggests bias. Low training error with a large validation gap suggests variance. More data usually helps variance more than bias.

### 3. Calibration is different from ranking

A classifier can order positive examples above negative examples while its probability values are overconfident. For bins `B_m`, a reliability curve compares:

<MathBlock latex="\operatorname{confidence}(B_m)=\frac{1}{|B_m|}\sum_{i\in B_m} p_i, \qquad \operatorname{accuracy}(B_m)=\frac{1}{|B_m|}\sum_{i\in B_m} y_i" />

A perfectly calibrated model lies near the diagonal. A strong ROC-AUC and poor calibration are not contradictory: ranking and probability quality answer different questions.

### 4. Leakage is a causal shortcut

Leakage is any information available to the training procedure that would not be available at prediction time. A quick target-correlation smoke test can flag a feature `x_j` whose correlation with `y` is suspiciously high:

<MathBlock latex="r_j = \frac{\sum_i (x_{ij}-\bar{x}_j)(y_i-\bar{y})}{\sqrt{\sum_i(x_{ij}-\bar{x}_j)^2}\sqrt{\sum_i(y_i-\bar{y})^2}}" />

Correlation is not a proof of leakage—real signals can be strong—but a copied target should stop the experiment immediately. Temporal leaks, duplicate rows, and preprocessing fitted before the split need separate checks.

<Gotcha>Never let the test set become a tuning set. If you inspect the test score after every feature change, the test set has become another training signal and its estimate is no longer honest.</Gotcha>

<KeyTakeaways>
- Cross-validation estimates a protocol, not an eternal truth; its split must match deployment.
- Learning curves separate underfitting from overfitting and data scarcity.
- Calibration asks whether probabilities mean what they say; ranking metrics ask a different question.
- Leakage is information from prediction time’s future entering training; a high score can be evidence of a bug.
- Every reported score needs a split, metric, uncertainty, and explicit failure modes.
</KeyTakeaways>
