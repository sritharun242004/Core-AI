<Hook>If one GPU cannot hold your model, which bytes should move, which should stay, and how do you prove the answer stayed the same?</Hook>

<Intuition>
A distributed model is not merely a model running on more computers. It is a schedule for owning tensors, transmitting them, and releasing them without changing the training objective. Think of a library: replication puts the whole collection in every branch, sharding assigns shelves to branches, and materialization temporarily borrows the shelves needed for one lesson.

Data parallelism replicates parameters and splits examples. Tensor parallelism splits matrix operations. Pipeline parallelism assigns layers to stages and trades idle bubbles against microbatching. Context parallelism splits sequence positions; queries need keys and values from other owners. They can coexist, but every combination adds a communication schedule that must be accounted for.

## The math, derived

### 1. Uneven batches require weighted reduction

Let rank r own n_r examples and let N be their total. A global mean loss is the sum of every local **sum**, divided by N. Averaging local means is only correct when local counts are equal. For multi-output mean-squared error, the denominator is the global number of target elements, not just examples.

<MathBlock latex="L=\frac{1}{N}\sum_r\sum_{i\in B_r}\ell_i,\qquad \nabla L=\sum_r\frac{n_r}{N}\nabla\bar L_r" />

Worked example: rank 0 has one example with gradient 4; rank 1 has three with mean gradient 0. The correct gradient is 1, not 2. An empty rank contributes zero. A simulator that averages rank means can pass equal-size tests and still teach the wrong algorithm.

### 2. ZeRO stages are ownership choices

For P parameters and W ranks, the illustrative mixed-precision Adam ledger uses 2 bytes for weights, 2 for gradients, 4 for master weights and 8 for two moments. Stage 0 replicates everything; stage 1 shards optimizer/master state; stage 2 also shards gradients; stage 3 also shards model weights.

<MathBlock latex="M_0=16P,\quad M_1=4P+12P/W,\quad M_2=2P+14P/W,\quad M_3=16P/W" />

These ideal expressions ignore padding. For P=1 billion and W=4, they give 16, 7, 5.5 and 4 **decimal GB per rank**, before activations and temporary buffers. The implementation reserves ceil(P/W) entries for sharded fields. Real bucket boundaries create additional padding. FSDP's allocations depend on the actual precision and optimizer implementation; the illustrative ledger is not a universal PyTorch memory formula.

A stage-3 forward all-gathers a layer, computes, and can reshard it. Backward may gather it again, then reduce-scatter gradients. A largest-layer full buffer can coexist with the persistent shard. Peak memory includes activations, communication workspaces, fragmentation, prefetch and backward intermediates: dividing parameter count by GPUs does not prove the model fits.

### 3. Count communication in one direction

An ideal ring all-reduce on a full S-byte buffer sends and receives the following **per rank**. Do not add sent and received bytes and then call that the link's one-direction payload.

<MathBlock latex="B_{\mathrm{allreduce,sent}}=2\frac{W-1}{W}S,\qquad B_{\mathrm{allgather,sent}}=B_{\mathrm{reduce\ scatter,sent}}=\frac{W-1}{W}S" />

Latency also depends on startup cost, topology, message size and overlap. Megatron-style tensor parallelism communicates activations within layers; pipeline stages transfer boundary activations and gradients; FSDP communicates parameter/gradient state. DeepSpeed ZeRO is a family of partitioning/offload mechanisms, not another name for tensor parallelism.

### 4. Online softmax makes blockwise attention exact

For one query, retain a running maximum m, normalization sum l and unnormalized weighted-value sum u. A new score block s and values V update these sufficient statistics:

<MathBlock latex="m'=\max(m,\max_j s_j),\quad l'=e^{m-m'}l+\sum_j e^{s_j-m'},\quad u'=e^{m-m'}u+\sum_j e^{s_j-m'}V_j,\quad o=u'/l'" />

Subtracting the joint maximum avoids overflow and rescales old contributions into the new coordinate system. With equal scores and values 2 and 6, the accumulator returns 4 independent of block order. Causal masking uses **global positions**, not local block indices. Fully masked/padded rows must return zero with zero gradients instead of computing infinity minus infinity.

The CPU loop visits K/V blocks in ring order and matches dense attention outputs and Q/K/V gradients. It does not communicate across machines. Ordinary autograd retains intermediates; a production memory-efficient ring kernel needs a custom recomputing backward and real collectives.

<Gotcha>Mathematical equivalence is not a speed benchmark. A sequential CPU loop can prove attention invariants while being slower and using more backward memory than optimized dense attention.</Gotcha>

## The code, from scratch

```python
import torch
from fsdp_ring_lab import dense_attention, ring_attention

q = torch.randn(2, 2, 7, 4, dtype=torch.float64, requires_grad=True)
k = torch.randn_like(q, requires_grad=True)
v = torch.randn(2, 2, 7, 3, dtype=torch.float64, requires_grad=True)
dense = dense_attention(q, k, v)
blocked = ring_attention(q, k, v, world_size=3, query_block_size=2)
torch.testing.assert_close(blocked, dense)
for actual, expected in zip(
    torch.autograd.grad(blocked.sum(), (q, k, v)),
    torch.autograd.grad(dense.sum(), (q, k, v)), strict=True
):
    torch.testing.assert_close(actual, expected)
```

### Hardware and kernels: learn the bottleneck

GPU warps execute many threads; coalesced global loads, shared-memory reuse and occupancy affect throughput. Matrix tensor cores accelerate selected matrix operations and dtypes, not arbitrary Python. CUDA exposes thread/block indexing and synchronization; Triton expresses tiled programs at a higher level. NVIDIA Triton Inference Server is a different product from the Triton kernel language.

TPUs use a different compiler/runtime and matrix-oriented architecture, commonly accessed through JAX/XLA. A kernel optimized for one memory hierarchy is not automatically optimal on another. Start a kernel exercise with vector addition, compare against a framework reference, then profile bandwidth and synchronization. Avoid claiming a kernel is faster from unsynchronized wall-clock timings.

Arithmetic intensity is operations per byte transferred. The roofline estimate bounds achievable FLOP/s by the smaller of peak compute and memory bandwidth times intensity. It is a diagnostic bound, not a prediction that includes communication or Python overhead.

<KeyTakeaways>
- Prove the global objective before optimizing collectives.
- Sharding reduces persistent state, not every peak allocation.
- Track sent, received and aggregate bytes separately.
- Stable online softmax permits exact block accumulation with global masks.
- Cloud correctness and performance are opt-in experiments, not inferred from CPU tests.
</KeyTakeaways>
